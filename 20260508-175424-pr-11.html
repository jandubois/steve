Executive Summary ¶

This PR turns rancher-desktop-steve into a self-contained dashboard binary: it downloads the Rancher Desktop dashboard tarball at build time, embeds it via //go:embed, and rewrites main.go to listen on a random localhost port, serve the embedded SPA with port substitution on text content, and proxy unmatched paths to steve. The Docker build and Drone pipeline come out; a cross-platform Makefile and a hardened release workflow go in.

The structural shape is sound — single-port server, pinned dashboard checksum, loopback-only bind, .DELETE_ON_ERROR on tarball rules, explicit job permissions in the release workflow. Two problems block a clean merge. First, the author has already flagged that the tarball ships executables under platform-suffixed names (steve-darwin-amd64) where Rancher Desktop expects a stable name; this is captured under Acknowledged Limitations. Second, mime.TypeByExtension is the wrong predicate for choosing what to rewrite — on most Linux distributions and on Windows, .js resolves to application/javascript, which fails the text/ prefix test and silently leaves the hardcoded :6120 port in the served JavaScript bundles. A handful of further Important issues cluster around os.Stdout handling (close + reassignment), startup ordering between port announcement and mux setup, and a panic risk if a future dashboard release adds a top-level directory that collides with an explicit mux pattern.

The build-system change has a workflow side-effect: a clean checkout can no longer run go build or go test ./... directly, because the //go:embed dashboard/* pattern requires files that only the Makefile generates. Documenting this and providing wrapper targets is cheaper than restructuring the embed.

mime.TypeByExtension consults the host OS database (on Linux/Alpine, /etc/mime.types; on Windows, the registry). Most distributions map .js to application/javascript, which fails the text/ prefix test and routes JS files through http.FileServerFS without port rewriting. The hardcoded http://127.0.0.1:6120/ references in the dashboard's compiled JavaScript bundles are then served untouched, and the dashboard makes API calls to a port that does not exist. The bug is silently OS-dependent: developers on macOS (where .js resolves to text/javascript via the builtin Go map) may see this work locally and break on user machines.

The same predicate also misclassifies .json (application/json), .svg (image/svg+xml), .xml (text/xml only via builtin — overridden to application/xml on most Linux installs), and .wasm (application/wasm). The current dashboard happens not to hit any of these, but the failure mode is "future dashboard refactor silently breaks the build."

Fix: stop relying on the OS MIME database. Decide what to rewrite by extension explicitly, or whitelist textual non-text/* MIME types.

ext := strings.ToLower(path.Ext(actualPath))
isTextual := strings.HasPrefix(mimeType, "text/") ||
    ext == ".js" || ext == ".mjs" || ext == ".json" || ext == ".svg"
if !isTextual {
    http.FileServerFS(subFS).ServeHTTP(w, r)
    return
}

A make rule that greps the unpacked dashboard for 127.0.0.1:6120 references and asserts every match lands in a file with an extension covered by the rewrite predicate would catch drift cheaply.

The reassignment at line 88 is also a data race. os.Stdout is a package-level *os.File pointer; goroutines started by config.ToServer and s.StartAggregation may read it (klog, logrus, controller libraries occasionally do) while the main goroutine writes it. Browsers cache 301 redirects aggressively, sometimes indefinitely. The listening port changes every launch, so a tab opened at http://127.0.0.1:<old-port>/ redirected on the previous run will skip the redirect on the next run and request /c/local/explorer directly. S6. go 1.26 in go.mod is unnecessarily restrictive Claude¶

The features this PR introduces — embed.FS (1.16+), mux.Handle("/{$}", ...) (1.22+), http.FileServerFS (1.22+) — only require Go 1.22. Setting the directive to 1.26 forces every developer and every CI image to install the very latest toolchain with no concrete benefit named in the commit message. Lower the floor unless a specific 1.26 fix is in use, in which case cite it in the commit body.

S8. Custom rewriter path strips HTTP caching for non-rewriting text files Gemini¶

The text-file branch reads the full file into memory, sets a Content-Type header, and writes the body via the replacer. It sets no ETag, Last-Modified, or Cache-Control headers, and ignores conditional GET headers. For files that never contain http://127.0.0.1:6120/ but happen to fall into the text bucket (stylesheets, source maps, the like), the browser refetches the full body on every reload — wasted bandwidth on the local socket but also wasted CPU on the server.

The constraint is partly intrinsic: index.html content depends on the runtime port, so caching across launches is wrong. A cheap fix is to pre-rewrite all rewriteable text files into a map[string][]byte at startup and serve them via http.ServeContent, which handles conditional GETs and uses the build time as Last-Modified. Files that do not actually contain the placeholder can then be served by http.FileServerFS directly.

Design Observations ¶

Concerns ¶

  • Static-asset serving duplicates pkg/ui instead of extending it (future) Claude. The repo already has pkg/ui/handler.go and pkg/ui/routes.go. The new logic in main.go is conceptually a new "mode" of UI handler — embedded FS rather than disk + download — but it lives inline in main.go rather than as another Handler variant. Folding the rewriter and SPA fallback into pkg/ui would keep main.go to wiring, make the rewriter unit-testable, and give the next person who needs a different UI source one place to look. (future)
  • The dashboard build leaks "compiled with port 6120 baked in" into the runtime (in-scope) Codex. The server compensates for this by string-replacing in served text assets and by keeping the /api/steve-port shim alive. A dashboard build option that uses window.location.origin or a <base href> — agreed with the dashboard project — would let this Go server shed the rewriter and the shim and become a normal static-file host. (future)

Strengths ¶

  • Loopback-only bind (net.IPv4(127, 0, 0, 1)) keeps the listener scoped to the local user. (in-scope) Codex Claude
  • The dashboard tarball is pinned by SHA-512 and wget'd from a tagged GitHub release, not latest or a branch. (in-scope) Codex Claude
  • .DELETE_ON_ERROR plus per-platform tarball rules in the Makefile prevent the classic "half-built tarball cached as fresh" bug. (in-scope) Claude
  • The new release workflow uses scoped per-job permissions:, splits build and release into separate jobs that pass artifacts via upload-artifact/download-artifact, and pins every action to a SHA. (in-scope) Claude

Testing Assessment ¶

The PR adds no tests for the new logic. The rewriter, mux wiring, and build-system changes are entirely untested. A small httptest-based test in a new main_test.go covers items 1–4 below cheaply by constructing a synthetic FS in place of the embed.

  1. SPA fallback: a request to a nonexistent path serves index.html, not 404 (rewriter, lines 154-158). Covers I1's regression-on-MIME indirectly.
  2. Port rewriting: a text fixture containing http://127.0.0.1:6120/ is rewritten to the listening port; a binary fixture passes through unchanged. This test must run on Linux to catch I1 — the developer macOS workflow will not.
  3. Mux routing: /api/steve-port returns the port, /c/local/explorer reaches the rewriter (not steve), /v1/... reaches steve.
  4. Mux collision: a synthetic dashboard FS containing a top-level c/ directory triggers the I4 collision check rather than panicking.
  5. Release artifact tests should untar each platform archive and assert the member name expected by Rancher Desktop post-install. Covers the Acknowledged Limitation.
  6. Clean-checkout validation: CI should run the documented build/test path with no preexisting dashboard/ directory. Covers I3.

Documentation Assessment ¶

  • The new file-level doc comment in main.go:1-5 correctly captures purpose, listening behavior, and the stdout-port convention.
  • app.Description will surface in --help, which is the right place for the "do not run manually" note.

Repo context updates ¶

  • Update pkg/ui description in deep-review-repo-overview.md. The current overview describes pkg/ui as "Static UI handler/router for the embedded dashboard," but pkg/ui/handler.go is the legacy disk + download UI handler — it has nothing to do with //go:embed. The embedded-dashboard logic lives in main.go for this fork.
  • Add: dashboard/ is generated, not committed. Future reviewers should know that //go:embed dashboard/* requires make dashboard/index.html to have run, that .gitignore excludes the directory, and that this blocks go test ./... and go build on a clean checkout. Without this context, agents waste tool calls trying to read files that do not exist in the worktree.
  • Add: the /api/steve-port endpoint is a deliberate compatibility shim, not dead code. The bundled dashboard probes it; a bare-number response keeps the dashboard's old two-port rewrite path disabled. Anyone who reads the "no longer used" comment in main.go and tries to remove the handler will silently break the dashboard.
