Retro: dependency types not explicitly covered ¶

  1. The inline-download verifier matcher misses *_SUM checksums when the destination hides behind one layer of ${VAR} indirection.
  • What was seen. scripts/install-envtest.sh:37 runs curl -sL -o "$DEST" "$URL" where line 32 sets DEST=/tmp/${TARBALL} from TARBALL="envtest-${ENVTEST_VERSION}-${OS}-${ARCH}.tar.gz". Line 39 then runs echo "${ENVTEST_SUM} ${DEST}" | sha512sum --check. scripts/install-k3d.sh:32 follows the same shape with K3D_SUM_<os>_<arch> and $DEST_DIR/k3d. Both download paths verify their bytes; the script flagged both verifier ✗.
  • Why current rules missed it. The Phase 2 spec accepts *_SHA256 / *_SUM / *_CHECKSUM / *_HASH / *_DIGEST variables when the variable's stem matches the destination's basename (after stripping archive suffixes). The matcher in inventory.py instead compares the ${ENVTEST_SUM} / ${K3D_SUM} variable name against the literal destination string ("$DEST" / "$DEST_DIR/k3d") and never resolves the indirection. Both sides stay placeholders, so the stem-match rule never fires.
  • Proposed change. Resolve one level of variable indirection in the verifier scan: when the curl/wget destination is ${VAR} or ${VAR}/literal, look back in the same file for the matching VAR=... assignment and substitute the resolved string before the basename/stem comparison. One level covers the common TARBALL=...; DEST=/tmp/$TARBALL pattern without turning the matcher into a shell evaluator. Add the rancher/shell *_SUM_${OS}_${ARCH} pattern to the regression fixtures so a future skip gets caught.
  1. The go.work.sum "missing" note fires when go.work is absent.
  • What was seen. The digest's Summary row for steve reads 4 with go.sum; workspace lock missing. The repo has no go.work — its four go.mod files are independent modules under ./ and ./gotools/*.
  • Why current rules missed it. inventory.py emits the workspace-lock note whenever it finds more than one go.mod, regardless of whether go.work exists. The skill text gates correctly (For workspaces (go.work present), also require go.work.sum); the implementation gates on the wrong condition.
  • Proposed change. Gate the go.workspace.has_lock check on Path('go.work').exists() (or the in-walk equivalent). Without a go.work, omit the note so the Summary row reads 4 with go.sum. Add a regression fixture with two independent go.mod files under different paths and assert the note stays absent.
