## Executive Summary

This PR turns `rancher-desktop-steve` into a self-contained dashboard
binary: it downloads the Rancher Desktop dashboard tarball at build
time, embeds it via `//go:embed`, and rewrites `main.go` to listen on a
random localhost port, serve the embedded SPA with port substitution
on text content, and proxy unmatched paths to steve. The Docker
build and Drone pipeline come out; a cross-platform Makefile and a
hardened release workflow go in.

The structural shape is sound — single-port server, pinned dashboard
checksum, loopback-only bind, `.DELETE_ON_ERROR` on tarball rules,
explicit job permissions in the release workflow. Two problems block a
clean merge. First, the author has already flagged that the tarball
ships executables under platform-suffixed names (`steve-darwin-amd64`)
where Rancher Desktop expects a stable name; this is captured under
Acknowledged Limitations. Second, `mime.TypeByExtension` is the wrong
predicate for choosing what to rewrite — on most Linux distributions
and on Windows, `.js` resolves to `application/javascript`, which fails
the `text/` prefix test and silently leaves the hardcoded `:6120` port
in the served JavaScript bundles. A handful of further Important issues
cluster around `os.Stdout` handling (close + reassignment), startup
ordering between port announcement and mux setup, and a panic risk if a
future dashboard release adds a top-level directory that collides with
an explicit mux pattern.

The build-system change has a workflow side-effect: a clean checkout
can no longer run `go build` or `go test ./...` directly, because the
`//go:embed dashboard/*` pattern requires files that only the Makefile
generates. Documenting this and providing wrapper targets is cheaper
than restructuring the embed.

## Important Issues

I1. **`mime.TypeByExtension` skips port rewriting on most Linux distributions and on Windows** — `main.go:159-164` [Gemini 3.1 Pro, Claude Opus 4.7]

```go
mimeType := mime.TypeByExtension(path.Ext(actualPath))
if !strings.HasPrefix(mimeType, "text/") {
    // For non-text files, just serve them directly without rewriting.
    http.FileServerFS(subFS).ServeHTTP(w, r)
    return
}
```

`mime.TypeByExtension` consults the host OS database (on Linux/Alpine,
`/etc/mime.types`; on Windows, the registry). Most distributions map
`.js` to `application/javascript`, which fails the `text/` prefix test
and routes JS files through `http.FileServerFS` without port
rewriting. The hardcoded `http://127.0.0.1:6120/` references in the
dashboard's compiled JavaScript bundles are then served untouched, and
the dashboard makes API calls to a port that does not exist. The bug
is silently OS-dependent: developers on macOS (where `.js` resolves to
`text/javascript` via the builtin Go map) may see this work locally and
break on user machines.

The same predicate also misclassifies `.json` (`application/json`),
`.svg` (`image/svg+xml`), `.xml` (`text/xml` only via builtin — overridden
to `application/xml` on most Linux installs), and `.wasm`
(`application/wasm`). The current dashboard happens not to hit any of
these, but the failure mode is "future dashboard refactor silently breaks
the build."

Fix: stop relying on the OS MIME database. Decide what to rewrite by
extension explicitly, or whitelist textual non-`text/*` MIME types.

```go
ext := strings.ToLower(path.Ext(actualPath))
isTextual := strings.HasPrefix(mimeType, "text/") ||
    ext == ".js" || ext == ".mjs" || ext == ".json" || ext == ".svg"
if !isTextual {
    http.FileServerFS(subFS).ServeHTTP(w, r)
    return
}
```

A `make` rule that greps the unpacked dashboard for `127.0.0.1:6120`
references and asserts every match lands in a file with an extension
covered by the rewrite predicate would catch drift cheaply.

I2. **Closing `os.Stdout` and reassigning the package variable is unsafe on two axes** — `main.go:82-89` [Gemini 3.1 Pro, Claude Opus 4.7]

```go
if _, err := fmt.Printf("%d\n", port); err != nil {
    return err
}
if err := os.Stdout.Close(); err != nil {
    return err
}
os.Stdout = os.Stderr
```

The close at line 85 frees file descriptor 1. On POSIX systems the
kernel reassigns descriptor 1 to the next file or socket the process
opens, and `s.StartAggregation(ctx)` (line 62, called *before* this
close) starts goroutines that may open files, sockets, or watchers.
Any cgo code or third-party library that issues a raw `write(1, ...)`
will then write into whichever fd-1-numbered resource the runtime has
since acquired — corrupting an unrelated socket or file with no
indication of the misroute.

The reassignment at line 88 is also a data race. `os.Stdout` is a
package-level `*os.File` pointer; goroutines started by
`config.ToServer` and `s.StartAggregation` may read it (klog, logrus,
controller libraries occasionally do) while the main goroutine writes
it. The Go race detector flags this; on 32-bit ARM the read can tear.

Fix: keep fd 1 occupied by duplicating fd 2 or `/dev/null` over it,
and avoid mutating the package variable. Print the port first, then
duplicate, then start the goroutines:

```go
// After printing the port, redirect fd 1 to fd 2 instead of closing.
if err := syscall.Dup2(int(os.Stderr.Fd()), int(os.Stdout.Fd())); err != nil {
    return err
}
```

Windows lacks `Dup2`; gate on `GOOS` or restructure so all goroutines
start *after* the redirect, eliminating the race.

I3. **A clean checkout cannot run `go build` or `go test ./...`** — `main.go:30-31`, `.gitignore:3` [Codex GPT 5.5]

```go
//go:embed dashboard/*
var dashboardFiles embed.FS
```

`.gitignore` excludes `/dashboard/`, and only `make dashboard/index.html`
populates it (via `wget` + `tar`). On a fresh clone, `go test ./...`
fails immediately with `pattern dashboard/*: no matching files found`,
and so does any IDE that runs `go build` on save. This breaks the
standard "`go test ./...` is supposed to work" expectation that every
contributor (and `gopls`) carries in.

Fix: either commit a stub `dashboard/.keep` plus an SPA-stub `index.html`
so the embed pattern compiles before `make` runs, or add `make build`
and `make test` targets that depend on `dashboard/index.html` and
document them in the README. A build-tag split that lets the package
compile without generated assets is also viable but heavier.

```make
.PHONY: build test
build: dashboard/index.html
	go build -o rancher-desktop-app-dashboard .
test: dashboard/index.html
	go test ./...
```

I4. **`http.ServeMux` registration loop will panic at startup if a future dashboard release adds a colliding top-level entry** — `main.go:100,105-115,117` [Claude Opus 4.7]

```go
mux.Handle("/c/", rewriter)
// ...
files, err := dashboardFiles.ReadDir("dashboard")
// ...
for _, f := range files {
    if f.IsDir() {
        mux.Handle("/"+f.Name()+"/", http.HandlerFunc(rewriter))
    } else {
        mux.Handle("/"+f.Name(), http.HandlerFunc(rewriter))
    }
}
// ...
mux.Handle("/api/steve-port", ...)
```

`http.ServeMux.Handle` panics on duplicate pattern registration. If a
future dashboard release adds a top-level directory named `c/` (or a
file named `api`), the loop calls `mux.Handle("/c/", ...)` again — and
the binary panics on every launch, with no opportunity for the new
dashboard tarball to be rolled back without recompiling. The only
gating mechanism today is "the current dashboard happens not to do
this," and the build performs no validation.

Fix: enumerate the explicit patterns, skip collisions in the loop, and
fail loudly at startup so the regression surfaces in CI rather than at
launch time.

```go
explicit := map[string]struct{}{"/c/": {}, "/api/steve-port": {}}
for _, f := range files {
    var pat string
    if f.IsDir() {
        pat = "/" + f.Name() + "/"
    } else {
        pat = "/" + f.Name()
    }
    if _, conflict := explicit[pat]; conflict {
        return fmt.Errorf("dashboard asset %q collides with explicit handler", pat)
    }
    mux.Handle(pat, rewriter)
}
```

I5. **The port is announced and stdout is closed before mux setup completes; a setup error after that drops the caller's queued connection** — `main.go:82-89,105-115,135` [Claude Opus 4.7]

```go
port := listener.Addr().(*net.TCPAddr).Port
// ... rewriteHandler(port) ...
if _, err := fmt.Printf("%d\n", port); err != nil { return err }
if err := os.Stdout.Close(); err != nil { return err }
// ... mux registrations, dashboardFiles.ReadDir(...) ...
if err := server.Serve(listener); err != nil && !errors.Is(err, http.ErrServerClosed) {
```

The TCP listener exists from line 66, so the kernel buffers SYNs and
completes accepts at the kernel level the moment the caller learns the
port. Between the port announcement (line 82) and `server.Serve`
(line 135), the function performs further fallible setup —
`dashboardFiles.ReadDir`, `mux.Handle` registrations (which can panic;
see I4) — and any error or panic in that window leaves the caller
holding a port number whose queued connections will be reset by the
deferred `listener.Close`.

Fix: complete every fallible step before announcing the port. Reorder
so `rewriteHandler`, `ReadDir`, and the mux registrations run first;
print the port only after the server is ready to actually accept.

The fix interacts cleanly with I2 — printing the port and redirecting
stdout can happen as the last step before `server.Serve`, eliminating
both races at once.

## Suggestions

S1. **Hoist `strings.NewReplacer` out of the per-request closure** — `main.go:184-186` [Gemini 3.1 Pro, Claude Opus 4.7]

```go
return func(w http.ResponseWriter, r *http.Request) {
    // ...
    replacer := strings.NewReplacer(
        "http://127.0.0.1:6120/",
        fmt.Sprintf("http://127.0.0.1:%d/", port))
    if _, err := replacer.WriteString(w, string(contents)); err != nil { ... }
}
```

The replacer depends only on `port`, which is fixed at startup, but the
closure reallocates it on every request. Build it once in
`rewriteHandler` and capture it in the closure.

```go
replacer := strings.NewReplacer(
    "http://127.0.0.1:6120/",
    fmt.Sprintf("http://127.0.0.1:%d/", port))
return func(w http.ResponseWriter, r *http.Request) {
    // ... use replacer ...
}
```

S2. **Use 302 or 307 instead of `http.StatusMovedPermanently` for the root redirect** — `main.go:96-98` [Claude Opus 4.7]

```go
mux.Handle("/{$}", http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
    http.Redirect(w, r, "/c/local/explorer", http.StatusMovedPermanently)
}))
```

Browsers cache 301 redirects aggressively, sometimes indefinitely. The
listening port changes every launch, so a tab opened at
`http://127.0.0.1:<old-port>/` redirected on the previous run will skip
the redirect on the next run and request `/c/local/explorer` directly.
That works today because the destination lives on the same server, but
any future redirect target change leaves users with cached 301s on a
dead URL until they manually clear their browser cache. Switching to
`http.StatusFound` (302) or `http.StatusTemporaryRedirect` (307) avoids
the lock-in.

S3. **The `/api/steve-port` handler comment is wrong; the bundled dashboard still calls it** — `main.go:116-119` [Codex GPT 5.5, Claude Opus 4.7]

```go
// Handle the steve-port API, which is no longer used.
mux.Handle("/api/steve-port", http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
    fmt.Fprintf(w, "%d", port)
}))
```

The bundled dashboard's compiled JS (`dashboard/js/index.70bf8115.js`)
still probes `/api/steve-port`. The bare-number response keeps the old
two-port rewrite path in the dashboard disabled, so the endpoint is in
fact a deliberate compatibility shim — not dead code. The misleading
comment makes it easy for the next maintainer to "clean up" the handler
and silently break the dashboard's startup path.

Fix: rename the comment to describe the actual contract, and set an
explicit `Content-Type` so the response stays a plain integer rather
than whatever sniffing produces.

```go
// Compatibility shim for the bundled dashboard plugin: it probes this
// endpoint, and a bare-number response keeps the old two-port rewrite
// disabled.
mux.Handle("/api/steve-port", http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
    w.Header().Set("Content-Type", "text/plain; charset=utf-8")
    fmt.Fprintf(w, "%d", port)
}))
```

S4. **The replacer matches only one literal form of the placeholder URL** — `main.go:184-186` [Claude Opus 4.7]

```go
replacer := strings.NewReplacer(
    "http://127.0.0.1:6120/",
    fmt.Sprintf("http://127.0.0.1:%d/", port))
```

`http://127.0.0.1:6120` (no trailing slash), `http://localhost:6120/`,
and bare `127.0.0.1:6120` are all plausible forms a future dashboard
build might emit. The current bundle apparently only uses the
trailing-slash form, but a build-system change in the dashboard could
introduce a variant that the replacer misses, and the dashboard would
silently call the wrong port.

Fix: either coordinate with the dashboard project to guarantee one
canonical form (and assert it at `make` time with a grep), or expand
the replacer to cover every variant up front.

S5. **The 10ms post-cancellation sleep is unjustified** — `main.go:124-127` [Claude Opus 4.7]

```go
go func() {
    <-ctx.Done()
    // Wait some time for steve stuff to shut down
    <-time.After(10 * time.Millisecond)
    timeoutCtx, cancel := context.WithTimeout(context.Background(), 5*time.Second)
    // ...
}()
```

Ten milliseconds is too short to be load-bearing for any real teardown
and not free either. Either delete the sleep — `server.Shutdown` and the
rest of steve's cancellation already run concurrently — or replace it
with whatever signal you are actually waiting for and document that.

S6. **`go 1.26` in `go.mod` is unnecessarily restrictive** — `go.mod:3` [Claude Opus 4.7]

The features this PR introduces — `embed.FS` (1.16+), `mux.Handle("/{$}", ...)`
(1.22+), `http.FileServerFS` (1.22+) — only require Go 1.22. Setting
the directive to 1.26 forces every developer and every CI image to
install the very latest toolchain with no concrete benefit named in the
commit message. Lower the floor unless a specific 1.26 fix is in use,
in which case cite it in the commit body.

S8. **Custom rewriter path strips HTTP caching for non-rewriting text files** — `main.go:165-189` [Gemini 3.1 Pro]

The text-file branch reads the full file into memory, sets a
`Content-Type` header, and writes the body via the replacer. It sets no
`ETag`, `Last-Modified`, or `Cache-Control` headers, and ignores
conditional GET headers. For files that never contain
`http://127.0.0.1:6120/` but happen to fall into the text bucket
(stylesheets, source maps, the like), the browser refetches the full
body on every reload — wasted bandwidth on the local socket but also
wasted CPU on the server.

The constraint is partly intrinsic: `index.html` content depends on the
runtime port, so caching across launches is wrong. A cheap fix is to
pre-rewrite all rewriteable text files into a `map[string][]byte` at
startup and serve them via `http.ServeContent`, which handles
conditional GETs and uses the build time as `Last-Modified`. Files that
do not actually contain the placeholder can then be served by
`http.FileServerFS` directly.

## Design Observations

### Concerns

- **Static-asset serving duplicates `pkg/ui` instead of extending it (future)** [Claude Opus 4.7]. The repo already has `pkg/ui/handler.go` and `pkg/ui/routes.go`. The new logic in `main.go` is conceptually a new "mode" of UI handler — embedded FS rather than disk + download — but it lives inline in `main.go` rather than as another `Handler` variant. Folding the rewriter and SPA fallback into `pkg/ui` would keep `main.go` to wiring, make the rewriter unit-testable, and give the next person who needs a different UI source one place to look. (future)

- **The dashboard build leaks "compiled with port 6120 baked in" into the runtime** (in-scope) [Codex GPT 5.5]. The server compensates for this by string-replacing in served text assets and by keeping the `/api/steve-port` shim alive. A dashboard build option that uses `window.location.origin` or a `<base href>` — agreed with the dashboard project — would let this Go server shed the rewriter and the shim and become a normal static-file host. (future)

### Strengths

- Loopback-only bind (`net.IPv4(127, 0, 0, 1)`) keeps the listener scoped to the local user. (in-scope) [Codex GPT 5.5, Claude Opus 4.7]
- The dashboard tarball is pinned by SHA-512 and `wget`'d from a tagged GitHub release, not `latest` or a branch. (in-scope) [Codex GPT 5.5, Claude Opus 4.7]
- `.DELETE_ON_ERROR` plus per-platform tarball rules in the Makefile prevent the classic "half-built tarball cached as fresh" bug. (in-scope) [Claude Opus 4.7]
- The new release workflow uses scoped per-job `permissions:`, splits build and release into separate jobs that pass artifacts via `upload-artifact`/`download-artifact`, and pins every action to a SHA. (in-scope) [Claude Opus 4.7]

## Testing Assessment

The PR adds no tests for the new logic. The rewriter, mux wiring, and
build-system changes are entirely untested. A small `httptest`-based
test in a new `main_test.go` covers items 1–4 below cheaply by
constructing a synthetic FS in place of the embed.

1. SPA fallback: a request to a nonexistent path serves `index.html`,
   not 404 (rewriter, lines 154-158). Covers I1's regression-on-MIME
   indirectly.
2. Port rewriting: a text fixture containing `http://127.0.0.1:6120/`
   is rewritten to the listening port; a binary fixture passes through
   unchanged. **This test must run on Linux** to catch I1 — the
   developer macOS workflow will not.
3. Mux routing: `/api/steve-port` returns the port, `/c/local/explorer`
   reaches the rewriter (not steve), `/v1/...` reaches steve.
4. Mux collision: a synthetic dashboard FS containing a top-level `c/`
   directory triggers the I4 collision check rather than panicking.
5. Release artifact tests should untar each platform archive and
   assert the member name expected by Rancher Desktop post-install.
   Covers the Acknowledged Limitation.
6. Clean-checkout validation: CI should run the documented build/test
   path with no preexisting `dashboard/` directory. Covers I3.

## Acknowledged Limitations

- **Tarball binary names are wrong, breaking Rancher Desktop post-install** — author general comment by @mook-as: *"The built executables are the wrong name (inside the tarball), breaking Rancher Desktop post-install."* The Makefile produces `release/steve-<platform>.tar.gz` containing `steve-<platform>` (or `.exe`), but `app.Name = "rancher-desktop-app-dashboard"` (`main.go:40`) and Rancher Desktop's installer expects a stable name. **This must be resolved before merge** but is correctly tracked here rather than as a finding because the author already owns it. Suggested fix shape: build the binary at the desired name, or rename it inside the tarball:

  ```make
  APP_NAME := rancher-desktop-app-dashboard
  release/steve-$(1).tar.gz: dashboard/index.html $(GOLANG_SOURCES) $(MAKEFILE_LIST)
      mkdir -p "$$(@D)/$(1)"
      env GOOS=$(call GOOS_FOR,$(1)) GOARCH=$(call GOARCH_FOR,$(1)) \
          go build -ldflags '-s -w' -trimpath \
          -o "$$(@D)/$(1)/$(APP_NAME)$(call EXE_SUFFIX,$(1))"
      tar -czf "$$@" -C "$$(@D)/$(1)" "$(APP_NAME)$(call EXE_SUFFIX,$(1))"
  ```

```diff
+	tar -czf "$$@" -C "$$(@D)" "steve$(call EXE_SUFFIX,$(1))"
+	rm -f "$(@D)/steve$(call EXE_SUFFIX,$(1))"
```

The `tar` command archives the executable using `$(+F)`, which resolves to the platform-specific name (e.g., `steve-darwin-amd64`). This breaks the Rancher Desktop post-install script, which expects the binary inside the tarball to be named `steve` (or `steve.exe` on Windows), as noted by @mook-as. 

Fix: Copy or rename the executable to the expected name before archiving it.

#### Important Issues

**I1. JavaScript files skip port rewriting on Linux/Windows** — `main.go:152-157` (important, gap)

```go
		mimeType := mime.TypeByExtension(path.Ext(actualPath))
		if !strings.HasPrefix(mimeType, "text/") {
			// For non-text files, just serve them directly without rewriting.
			http.FileServerFS(subFS).ServeHTTP(w, r)
			return
		}
```

`mime.TypeByExtension` relies on the host OS's mime database (e.g., `/etc/mime.types`). On many Linux distributions (like Ubuntu and Alpine) and Windows, `.js` files resolve to `application/javascript` or `application/x-javascript`. The `strings.HasPrefix(mimeType, "text/")` check evaluates to false on these systems, causing JS files to be served via `http.FileServerFS` without having the hardcoded `6120` port rewritten. This breaks dashboard API calls.

Fix: Check explicitly for the `.js` extension or its specific `application/*` mime types:
```go
		ext := strings.ToLower(path.Ext(actualPath))
		mimeType := mime.TypeByExtension(ext)
		if !strings.HasPrefix(mimeType, "text/") && ext != ".js" && mimeType != "application/javascript" {
```

**I2. Closing os.Stdout creates a file descriptor reuse hazard** — `main.go:82-84` (important, regression)

```go
	if err := os.Stdout.Close(); err != nil {
		return err
	}
	os.Stdout = os.Stderr
```

Calling `os.Stdout.Close()` explicitly frees OS file descriptor 1. On POSIX systems, the lowest available file descriptor is automatically assigned to the next opened file or socket. If any native C library, Cgo code, or third-party package writes natively to stdout (FD 1), it will silently write into that newly opened network socket or file, causing severe data corruption.

Fix: Do not free the descriptor. To safely close the pipe back to Rancher Desktop while keeping FD 1 occupied, redirect `/dev/null` over it using `unix.Dup2` (on POSIX), or pass the port via a dedicated file/socket instead of relying on `stdout`.

**I3. Custom file server strips HTTP caching headers** — `main.go:160-176` (important, regression)

```go
		contents, err := subFS.(fs.ReadFileFS).ReadFile(actualPath)
		// ... (error handling) ...
		w.Header().Set("Content-Type", mimeType)
		replacer := strings.NewReplacer(...)
```

The custom rewrite handler manually reads and writes the file contents but implements no HTTP caching mechanism (no `ETag`, `Last-Modified`, or `Cache-Control` headers) and ignores conditional GET requests (`If-None-Match`). By bypassing `http.FileServer` for text files, browsers are forced to download a 200 OK payload for large files (like the ~10MB JS vendor chunk) on every single page reload, heavily degrading dashboard load times.

Fix: Pre-rewrite the text files into an in-memory map at startup, and serve the cached byte arrays using `http.ServeContent` to automatically handle HTTP caching negotiations.

**S1. Inefficient string replacer instantiation** — `main.go:175-177` (suggestion, enhancement)

```go
		replacer := strings.NewReplacer(
			"http://127.0.0.1:6120/",
```
